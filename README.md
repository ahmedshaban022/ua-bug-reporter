# UA Bug Reporter

A smart, lightweight Chrome extension (Manifest V3) that turns a broken
page into a **ready-to-paste markdown bug report in one click**: page and
environment info (build id, release, flags), console errors with stacks,
failed network requests with status codes, storage summary, and a
viewport screenshot — assembled into your tracker's format with an empty
"Steps to reproduce" waiting for you.

No dependencies, no build step, ~35 KB of plain JS.

## Install (unpacked)

1. Open `chrome://extensions`
2. Enable **Developer mode** (top right)
3. Click **Load unpacked** and select this folder (`ua-bug-reporter`)

## Use

- Toolbar → **Build report** (or **Alt+Shift+B**, or right-click → *Build bug report for this page*)
- The full report opens in its own page: **Copy markdown**, **Download .md**, **Download screenshot**
- Popup shows a live summary (errors / warnings / failed requests) and the last 10 reports as history

### Console capture (opt-in, per site)

JavaScript errors only exist from page load onward, so capturing them
needs a hook installed at `document_start`:

1. Popup → **Arm console capture for this site** — Chrome asks for
   permission to *that origin only* (never all sites), the page reloads,
   and `console.error` / `console.warn` / uncaught errors / unhandled
   rejections are recorded into a capped ring (200 entries)
2. Reproduce the bug
3. **Build report** — everything is included, stacks and all
4. **Disarm** removes the hook and revokes the per-origin permission

Without arming you still get the retroactive parts: failed requests
reconstructed from the Resource Timing API (status per entry), page/env
facts, storage summary, and the screenshot.

## What makes it careful

| Concern | Behavior |
|---|---|
| permissions | `activeTab` + `scripting` at install; console capture needs an explicit per-origin grant (`optional_host_permissions`) you can revoke anytime |
| privacy | reports live in `chrome.storage.local` on your machine only; history is capped at 10 reports / 8 MB with oldest-first eviction |
| request truth | `responseStatus` (Chrome 109+) is the primary signal; the fallback only fires for same-origin fetch/xhr/beacon so cross-origin entries without Timing-Allow-Origin never false-positive |
| noise limits | console ring capped at 200, entries truncated, env keys capped at 20, report text kept pasteable |
| hooks | `console.error/warn` wrap once and always call through to the real console — DevTools output is unchanged |

## Structure

```
manifest.json            MV3 manifest (activeTab, scripting, storage, clipboardWrite; optional host perms)
background.js            service worker: report building, arming, screenshot, history
shared/reportcore.js     pure report logic (dual-format module — fully unit-tested)
shared/inject.js         isolated-world collector + MAIN-world buffer readers
content/console-hook.js  MAIN-world ring buffer for console/error events (armed origins only)
content/collect.js       isolated-world page-fact collector
popup/                   build / arm / settings UI
pages/report.html        report viewer: rendered markdown + screenshot + copy/download + history
icons/                   generated by tools/gen-icons.js
```

## Verify

```
node test/run-tests.js                       # unit tests (report logic)
NODE_PATH=… node test/e2e.js                 # real-Chrome e2e (see header comment)
node tools/gen-icons.js                      # regenerate icons
NODE_PATH=… node tools/make-screenshot.js    # regenerate the store screenshot
```

The e2e suite serves a demo page that fails in every way a report cares
about (404 + 500 fetches, `console.error` with an `Error`, a warning, a
late uncaught throw), loads the real hook + collector, and asserts the
generated markdown contains all of it — plus ring-cap and idempotent
re-injection checks.

## Notes & limits

- The screenshot is viewport-only (what you see is what you file); long-page captures belong to a dedicated diff tool.
- `captureVisibleTab` needs the extension gesture — building from the popup, shortcut, or context menu all qualify.
- Arming survives until the browser restarts by design (`persistAcrossSessions: false`); the popup shows and can clear the state either way.
- Request bodies/headers are not recorded (Resource Timing has none); statuses and timing are.
- The console hook sees the page's own console output; it cannot recover errors from before it was armed.
